# Google Summer of Code 2027 — project ideas

**Hawkeye** lets ordinary Nigerians keep their own record of the result announced at
their polling unit: a photo of the official result sheet (form EC8A), the counts,
signed on the observer's phone and added to a public hash chain whose head is published
to Sigstore's Rekor transparency log. It is free, open source (MIT), non-partisan, and
built for cheap Android phones on weak networks, in English, Hausa, Igbo and Yoruba.
Its first nationwide use is Nigeria's general election on 16 January 2027.

**Before you apply:** read [CONTRIBUTING.md](../CONTRIBUTING.md), get `app/` running
locally, and send a small pull request (a fix, a test, or a translation review). Then
open an issue titled `GSoC 2027: <idea>` with your plan — we would rather discuss a
proposal early than read it cold.

**Mentors:** Osaretin Jerry Osagie ([@HawkeyeNG](https://github.com/HawkeyeNG)) and a
second mentor per project, named before the organisation list is announced.

Sizes follow GSoC's scheme: small ≈ 90 h, medium ≈ 175 h, large ≈ 350 h.

## 1. A verifier that runs in the browser

The [hawkeye-verify](https://github.com/hawkeye-ng/hawkeye-verify) command-line tool
replays the whole public chain, checks one race's Merkle proof, and checks Rekor's own
proofs and signatures. Most people who should check will not open a terminal — and the
in-browser check on hawkeye.com.ng is served by us, which is exactly what an
independent check should not depend on.

- **Outcome:** the hawkeye-verify checks as a static page hosted *outside* our
  infrastructure (e.g. GitHub Pages from the hawkeye-verify repo): it fetches the public
  chain, replays it with Web Crypto, verifies a race proof and the Rekor inclusion, and
  explains each result in plain language; shared test vectors with the CLI so the two
  can never disagree.
- **Skills:** JavaScript/TypeScript, hashing and Merkle trees (we will teach the rest).
- **Size / difficulty:** medium · intermediate.

## 2. Reporting that survives a bad network

Polling units are often where the signal is worst. Reports queue in an outbox
(`app/outbox.js`, Background Sync) and photos upload directly (`app/direct-upload.js`).

- **Outcome:** resumable photo uploads, a clear "saved on this phone / sent" state the
  observer can trust, and a repeatable test that submits reports under throttled
  2G/3G and flaky connectivity (Playwright network emulation) — with numbers before and
  after.
- **Skills:** JavaScript, service workers, IndexedDB.
- **Size / difficulty:** medium · intermediate.

## 3. An open benchmark for reading result sheets

Result sheets are public documents, and reading them automatically is how thousands of
reports become a readable total. Today nobody can say, in public, how accurate any
reader is on real, photographed, handwritten Nigerian sheets.

- **Outcome:** a labelling tool and schema for sheet images (per-party counts, totals,
  unit code), a small openly licensed labelled set, and a model-agnostic evaluation
  harness that scores any reader (OCR or vision-language model) field by field, with
  a baseline run.
- **Skills:** Python; some computer vision or ML evaluation experience.
- **Size / difficulty:** large · advanced.

## 4. Hausa, Igbo and Yoruba — a translation workflow

Every string ships in four languages (`app/i18n/`, `native/src/lib/i18n/`), and machine
drafts are reviewed by people. The review itself is still ad hoc.

- **Outcome:** a lightweight review tool (show each string in context, flag,
  suggest, approve) that writes back to the JSON files; coverage checks in CI for keys
  missing from any language; a shared glossary so an election term is translated the
  same way everywhere.
- **Skills:** JavaScript; fluency in Hausa, Igbo or Yoruba is a strong plus.
- **Size / difficulty:** small · beginner-friendly.

## 5. Accessibility and low-end phones

`tests/ui` runs an automated audit of every page. It currently reports hundreds of
findings — mostly tap targets under 44 px and low contrast.

- **Outcome:** the audit's findings fixed across the web app, the audit made a
  gating CI check, and a performance budget measured on an entry-level Android phone.
- **Skills:** HTML, CSS, accessibility basics, Playwright.
- **Size / difficulty:** small–medium · beginner-friendly.

## 6. Closing the gap between the web and the app

The React Native app (`native/`) trails the web app in places; the known gaps are
listed in [NATIVE-PARITY-GAPS.md](NATIVE-PARITY-GAPS.md).

- **Outcome:** an agreed subset of those gaps closed, each with a test, in all four
  languages.
- **Skills:** TypeScript, React Native / Expo.
- **Size / difficulty:** medium · intermediate.
